FA-ASMR 对齐工具 — 使用说明
================================

本工具基于注音台本 + 人声音频，做日语 ASMR 配音的强制对齐（打轴），
用于把每一句台本对应到音频里的精确起止时间。

-----------------------------------------------------------
一、首次使用前：放置 MMS-FA 模型权重（必须）
-----------------------------------------------------------
程序本身不含模型权重（约 1.2GB，因许可与体积原因不随包发布）。
请把权重文件放到以下位置（与 FA-ASMR.exe 同级）：

    FA-ASMR.exe 所在目录 / models / hub / checkpoints / model.pt

权重来源：原项目 moriwx/FA-Kara 使用的 MMS_FA 模型（torchaudio 的
MMS_FA 英文/日文对齐模型权重）。若本机可联网，首次运行时程序也会尝试
自动下载；若处于离线环境，请提前手动放置好上述文件。

-----------------------------------------------------------
二、运行方式
-----------------------------------------------------------
方式一（推荐）：双击 FA-ASMR.exe 打开图形界面，按提示拖入台本与音频。

方式二（命令行）：
    FA-ASMR.exe --cli --script 台本.txt --audio 音频.wav [--lora 权重.pt]

（LoRA 默认已内置 fa_asmr_e30.pt，通常无需指定。）

-----------------------------------------------------------
三、系统要求
-----------------------------------------------------------
- 操作系统：Windows（本程序为 Windows 打包版本）。
- 显卡：有 NVIDIA 显卡且装好 CUDA 驱动时，GPU 版自动使用 GPU 加速；
  CPU 版为纯 CPU 推理（无 GPU 加速，较慢但稳定，适合无显卡或只验证效果）。
- 两个版本都已内置相应 PyTorch（CPU 版为 embedded_torch 2.6.0，GPU 版为 CUDA 版 2.6.0），
  双击即可直接运行，无需任何安装。
- 若运行报错“缺少 xxx.dll”（多为 VC++ 运行库缺失或显卡驱动过旧）：
  请确认系统已安装最新 Visual C++ Redistributable 与 NVIDIA 驱动；
  CPU 版只依赖内置 CPU torch 与 VC++ 运行库，几乎不会缺 DLL。如需其它 CUDA 构建，可自行从源码构筑。

-----------------------------------------------------------
四、台本要求（重要，直接影响对齐质量）
-----------------------------------------------------------
1. 台本必须提前手工清洗：删去【不实际发音】的内容，例如
   说话人前缀（A/B、キャスト名）、括号里的动作/表情提示（笑、囁く）、
   场记标记（■、○）、纯数字场号、与音频对不上的段落。
   这些不会被“读出来”，留着只会干扰对齐。

2. 台本顺序必须与音频一致：本工具是“强制对齐”，要求台本
   第 1 行对应音频开头、第 2 行对应其后……不支持乱序、跳行、
   或一段音频对应多处台本。剪辑合集 / 总集编类素材往往对不齐。

-----------------------------------------------------------
五、效果说明（请先降低预期）
-----------------------------------------------------------
- 对齐基于 CTC 强制对齐，对清晰口播效果较好；
  喘息、呻吟、拟声（ん〜、あぁ…、くりくり…）等行时长容易偏短/塌缩，
  工具已内置 auto_repeat 等后处理尽量修补，但无法保证全部准确。
- 单句误差通常在百毫秒级；少数（约一成）长喘息/拟声行误差可能超过 1 秒，
  属当前方法的固有限制，非 bug。
- 本项目由 AI 在用户指导下编写，目前并不完善，请自行评估风险后使用。

-----------------------------------------------------------
六、设置文件（进阶，一般用户无需改动）
-----------------------------------------------------------
- fa_asmr_settings.json：GUI 用户设置（同目录，自动读写）。
- advanced_config.json：底层系统配置（CPU 线程数 / INT8 量化 /
  分块大小等），手编生效、且不会被 GUI 覆盖。

-----------------------------------------------------------
七、GUI 高级设置（点击「▶ 高级设置」展开，一般保持默认）
-----------------------------------------------------------
这些是适配不同机器 / 不同台本的实验开关，默认值是实测出的稳妥配置。
除非遇到明确问题，否则不要改；逐项说明取舍：

1. 设备 (dev)：cuda / cpu（仅 GPU 版显示 cuda 选项；CPU 版只有 cpu）
   - GPU 版默认有 N 卡自动用 cuda，否则回退 cpu。一般不用动。
   - 仅当想强制用 CPU 跑（更慢但更稳）时切换。

2. 显存缓冲(帧) (vram_chunk)：默认 6000（仅 GPU 版显示）
   - 仅 GPU 模式生效。MMS-FA 大模型按“块”送显存：值越大单次喂入越长
     → 更快但更吃显存；值越小越省显存但更慢。
   - 遇到显存不足（OOM 报错 / 崩溃）时调小（如 3000~4000）；显存充裕想提速可保持或略增。
   - 仅在 GPU 生效；CPU 模式看 advanced_config.json 的 cpu_chunk_cap。

3. 循环切除塌缩行重CTC(≤5次) (prune)：默认 开
   - 实验性后处理：对个别“塌缩成极短”的行反复切尾重跑 CTC，尽量拉长时长。
   - 一般保持默认开。若你发现某些短喘息行被过度拉长、或不信任此修补，可关掉
     退回纯全局 CTC 结果。

4. 行结束延长(秒) (end_extend)：默认 0，推荐 0.5~1.5
   - 给每行对齐终点额外向后延长若干秒（不会越过下一行起点），
     补偿 CTC 倾向“句尾早收”的偏短。
   - 0 = 不延长（最保守）；若听感上“上一句尾巴被切、下一句开头被抢”，
     设 0.5~1.5 可改善衔接。设多大都不会越过下一行，较安全。

-----------------------------------------------------------
八、进阶底层配置 advanced_config.json（手编，非 GUI）
-----------------------------------------------------------
用于 CPU 模式下的性能微调，GUI 高级面板不涉及。编辑后保存、重启 exe 生效；
此文件从不被 GUI 写回，手编内容不会被覆盖。

- cpu_threads：CPU 前向线程数，null = 自动取物理核数。
  多核机器想留资源给其它程序时可设较小值（如 4）。
- quantize_int8：CPU INT8 动态量化，null = 自动（CPU 开 / GPU 关）。
  绝大多数现代 CPU 开启后更快；个别老 CPU 上 INT8 反而慢可设 false。
- cpu_chunk_cap：CPU 单块帧数上限（默认 2000）。
  越大越占内存、越小越慢（注意力 O(n²)）；仅 CPU 生效，GPU 看 vram_chunk。
